# Assistant P2 — proposal inbox and weekly coaching

- Date: 2026-10-02
- Status: accepted
- Umbrella: `2026-10-02-assistant-architecture.md`. Decisions: ADR 0040. Builds on `diagnosis-v1` (ADR 0023).

## 1. Goal
Each week the assistant names **one 1% change** for the owner's system. It is backed by numbers, and when the change
can be made safely it is applied with one click. Every suggestion goes through a single inbox where it is applied or
dismissed. That inbox is the channel P3 (chat) and P4 (notifications) will reuse.

## 2. Proposal kinds (`coach-v1`)
Every kind is generated by code from the last 28 local days (today excluded). Its reason text is a template, so no
LLM is involved.

| kind | when | proposal | apply |
|---|---|---|---|
| `rule_minutes` | An active 실행 규칙 on an active process has `intended_minutes`, ≥ 3 finished timer sessions, and a median focused length < 60% of the intent (the diagnosis "tactic" threshold). | "‘…’ 규칙을 M분 → N분으로", where N = the median rounded to 5 (min 5). Linked focus habits with a larger target get N too. | Updates the protocol's minutes and those habits' targets. |
| `habit_days` | An active habit with ≥ 8 due days in the window and completion < 50%. | Keep only the weekdays held ≥ 50% of the time; if none, the single best weekday. Proposed only when that is a strict subset. | Updates the habit's weekdays. |
| `review` | Any other diagnosis signal of an active 변화: goal, strategy, planning, execution, recovery, or a tactic signal with no concrete fix. | The layer's SYSTEM QUESTION and evidence, with the screen to open. | Marks it confirmed and navigates. Nothing else changes. |

- **Ordering:** `rule_minutes` first, then `habit_days`, then `review` (lowest diagnosis layer first, as in ADR
  0023). The first item is the week's **focus**. At most 3 items are kept per week.
- **Freshness check before applying:** the applier re-reads the target. If the protocol or habit has changed since
  the proposal (different minutes or weekdays, or no longer active), it refuses with "이미 바뀌었습니다" and the
  proposal is closed as dismissed.
- **Dismissed** proposals for the same `kind + target` are not proposed again for 28 days.

## 3. Lifecycle
- **When it is generated:** lazily, when the 주간 회고 page shows the current week and no proposal exists for that
  week yet. Proposals are never backfilled for past weeks.
- **Statuses:** `proposed`, `applied` or `dismissed`, plus `decided_at`. When a week ends, its open proposals are
  shown as expired; no write happens.
- **Concurrency:** unique `(user_id, week_start, kind, target_key)` and one focus per user and week (partial unique
  index). Duplicate inserts are ignored.

## 4. UI
- **주간 회고, "코칭" section** (shown above the metrics for the displayed week):
  - The focus card: title, reason, evidence chips, and [적용] or [확인하고 이동] plus [넘기기].
  - Up to two other proposals.
  - A closed list: "이번 주 결정 (n)".
- **Scheduler brief:** a new row, "이번 주 1% 변화: …", links to `/scheduler/review#coaching` while the focus
  proposal is still open.

## 5. Data
`assistant_proposals` has these columns:
- `user_id`, `week_start`, `kind`, `target_key`;
- `title` (≤ 80), `reason` (≤ 300), `payload` jsonb, `evidence` jsonb;
- `focus`, `status`, `rules_version`, `created_at`, `decided_at`.

RLS:
- Own select, insert and delete. Delete exists only for E2E cleanup.
- Own update is granted on `status` and `decided_at` only.

## 6. Code
- `features/assistant/domain/coach.ts`: pure `coachProposals(input)` → drafts; `weekdayRates`; payload Zod schemas
  per kind.
- `features/assistant/queries/coach.queries.ts`: the coach input. It reuses `loadDirectionStatus` for the signals.
- `features/assistant/services/proposal.service.ts`:
  - `ensureWeeklyCoaching`;
  - `applyProposal`, which calls the existing direction and habit services so their validation applies;
  - `dismissProposal`.
- `features/assistant/actions/proposal.actions.ts`.
- `features/assistant/components/coaching-section.tsx`.

## 7. Testing
- **Unit:** the thresholds and rounding, weekday selection, ordering and focus, dismissed suppression, and the
  payload schemas.
- **SQL:** `assistant.sql` is extended with own-only access, update limited to the status columns, and one focus
  per week.
- **E2E `assistant-coaching.spec.ts`:**
  1. Seed a change with a process, a 40-minute rule and 3 short timer sessions on it.
  2. Open 주간 회고; the focus card offers 40 → 15 minutes.
  3. [적용] → the rule shows 15분.
  4. Then [넘기기] on a seeded habit proposal.
